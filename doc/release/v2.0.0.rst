*******************************************
Release 2.0.0 of this fork (unreleased)
*******************************************

The first release of this fork, branched from upstream ARMI 0.6.4 and numbered 2.0 to mark the fork, which is
independent of TerraPower, LLC. It adds a browser-based input editor in place of the wxPython one, fuel cycle
economics, replaces the blueprint YAML layer, fixes a set of long-standing reactor model bugs and makes common
operations much faster.

Browser-based input editor
==========================

ARMI now ships a browser-based editor for its inputs, and every application gets it as the ``gui`` entry point::

    $ python -m armi gui my-case.yaml

It is a front end to the same text files: anything it writes reads like hand-written YAML, and anything written by
hand opens in it. The server is standard library and the front end is plain JavaScript with no build step, so it needs
nothing beyond ARMI and runs anywhere ARMI does, including over SSH (``--no-browser``, or ``--host`` to serve beyond
loopback). It replaces the wxPython grid editor: the ``grids`` entry point and the ``grids`` extra are gone, and with
them ARMI's last GUI dependency.

The editor can also run the case it has open (**Run**, Ctrl+Enter) and follow its log in a docked console, with the
application it was started from, so a plugin's settings and physics come along.

Fuel cycle economics
====================

A new economics plugin (``armi.physics.economics``) costs a reactor's whole fuel cycle and writes a four-page PDF
report for core designers and decision makers alike. Turn it on with ``econFuelCost: true``, and
``econFuelCostReport: true`` for the report.

* **The initial core, mine to spent fuel:** natural uranium (lb U\ :sub:`3`\ O\ :sub:`8`), conversion, separative work,
  depleted tails and fabrication, each with its quantity and cost. The tails assay can be optimized for the prices.
* **Reloads** are the fresh assemblies the run's fuel management actually loads at the start of each cycle, or a
  projected fraction of the initial core (``econReloads``).
* **The levelized fuel cycle cost** ($/MWh) covers every load and spent fuel (``econBackEndCost``), with each
  front-end step paid its lead time before loading (``econLeadTime*``), discounted against the plant's generation.
* **For core designers:** discharge burnup, specific power, uranium and separative work per GWh, uranium
  utilization, and each cycle's fresh fuel against the electricity it makes.
* **For decision makers:** cumulative cash flow, the sensitivity of the cost to every price, the discount rate and
  the capacity factor, and the bridge from undiscounted to levelized cost.
* UO\ :sub:`2`, U-metal and TRISO each have their own fabrication price, the fuel form is detected from the materials,
  and every price is a setting.

New features
============

* Particle fuel: a ``particles:`` blueprint section describes TRISO-like particles layer by layer, and any component can
  hold them at a packing fraction (``particles: TRISO``, ``packingFraction: 0.35``). Each layer becomes a component of
  the block, counted per centimeter of block height so that masses scale with height (:ref:`particle-fuel`).
* New materials for gas-cooled reactors and TRISO fuel: ``SiC``, ``UCO`` (UC0.5O1.5) and ``Helium``.
* Block parameters for fuel pin temperatures and pin gas pressure.
* A material can declare that it never thermally expands.
* ENDF/B-VIII.1 DRAGLIB nuclide names are accepted in the elemental expansion.
* ``!include`` can be written as the value of a key in blueprints.

Blueprints and YAML
===================

* Blueprints moved from ``yamlize`` to ``yamlSchema``, a document-backed YAML object mapping, and the ``yamlize``
  dependency is gone. Round-tripping a blueprint no longer corrupts zero values, and multi-line strings are written
  as literal block scalars so lattice maps stay readable.
* Parsed YAML is copied without breaking its anchors and merge keys, and an edit to a merged mapping no longer leaks
  into the mappings that merge it.
* An aliased block design is its own design rather than a second name for one.
* ``!include`` on the same line as its key is rejected instead of producing broken YAML.

Bug fixes
=========

* Power from ``powerDensity`` was too low in partial-core models.
* Axial expansion divided ``massHmBOL`` by the symmetry factor twice.
* Writing a full Cartesian lattice map dropped part of the core; a grid that cannot be written now says why.
* Fixes to mass conservation and meshes in the converters; assembly, core ring and excore collections; block area
  caching, homogenization pitch and composite density helpers; the blueprint area check, grid saving and location
  ordering; and ``ParameterCollection`` equality and backup restore for reshaped arrays.
* ``plotMatrix`` leaves the caller's colormap alone, and the visualization dumpers return themselves from
  ``__enter__``.

Performance
===========

* Getting and setting number densities on composites is much faster, nuclides are looked up by name with a
  dictionary, and the nuclide data is built once at import.
* Parameter collections fill without per-field checks, database syncs no longer force a full garbage collection,
  binary CCCC matrices are read in one call, and pin index lookup in ``HexBlock.assignPinIndices`` is O(1).
* The slowest tests are faster without losing coverage.

Project
=======

* Rebranded as a fork with a relaxed LLM policy, modernized CI, and Python 3.11 or newer.
* Logging goes through the standard library logger.
* The documentation builds without warnings against current Sphinx releases, and the README says how to build it.
* New files carry no copyright header; see ``CLAUDE.md`` for the notice policy.
